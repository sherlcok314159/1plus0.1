当涉及到采样时，比如初始化，就会有随机性，而每个元素对应着一个随机数，torch 会在内部调用 RNG（随机数生成器）来生成随机数序列，而 `set_seed` 的作用是让第一个随机数是一样的

在 cpu 上随机数序列是连续的，比如首先是 q 需要 16 个随机数，假如从 $r_{0}, r_{1}, \dots, r_{15}$，接着 k 也需要 16 个随机数，即 $r_{16}, r_{17}, \dots, r_{31}$；而另一种是一次性生成 48 个随机数，即 $r_{0}, r_{1}, \dots, r_{47}$，因而分开和合并初始化最终在 cpu 上是一样的

而在 cuda 上，q 的初始化与 cpu 上一样，但是轮到 k 时，会有一个 offset，而不是接着 q 的随机数开始生成，比如 $r_{256}, r_{257}, \dots$，所以分开和合并初始化最终在 cuda 上不一致

```python
import math

import torch

device = 'cpu'  # cuda or cpu


def set_seed():
    torch.manual_seed(42)
    torch.cuda.manual_seed(42)


# Split
set_seed()
q = torch.empty(4, 4, device=device)
k = torch.empty(4, 4, device=device)
v = torch.empty(4, 4, device=device)

# 默认的 Linear 初始化
torch.nn.init.kaiming_uniform_(q, a=math.sqrt(5))
torch.nn.init.kaiming_uniform_(k, a=math.sqrt(5))
torch.nn.init.kaiming_uniform_(v, a=math.sqrt(5))

# Fused
set_seed()
wqkv = torch.empty(12, 4, device=device)
torch.nn.init.kaiming_uniform_(wqkv, a=math.sqrt(5))
splits = wqkv.reshape(3, 4, 4).unbind(0)

print('q == split[0]:', torch.allclose(q, splits[0]))
print('k == split[1]:', torch.allclose(k, splits[1]))
print('v == split[2]:', torch.allclose(v, splits[2]))

"""
cpu
q == split[0]: True
k == split[1]: True
v == split[2]: True
cuda
q == split[0]: True
k == split[1]: False
v == split[2]: False
"""
```
